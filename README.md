# رتل | نموذج المصحف والتسميع

نموذج أولي على فرع `prototype/mushaf-recall`. لا يغيّر الموقع المنشور ولا يساوي تطبيق iOS أصليًا. تجربة الحفظ مستلهمة من OpenHafith، مع صفحة قراءة متصلة وخلفية ورقية هادئة بهوية رتل. لم تُنسخ صور أو ملفات أو هوية أي من التطبيقين المرجعيين.

## التجربة محليًا

يتطلب Node.js 22 أو أحدث:

```sh
npm ci
npm run dev
```

لتجربة النسخة المبنية، بما فيها التخزين دون اتصال:

```sh
npm run build
npm run preview
```

لا تفتح `index.html` مباشرة ولا تنشر مجلد المصدر. ناتج البناء هو `dist/`. محرك الصوت يحتاج HTTPS أو localhost وإذن الميكروفون. عنوان HTTP على الشبكة المحلية لا يكفي عادةً لميكروفون الهاتف. أول بناء ينزّل نموذجًا حجمه نحو 66 ميغابايت وملفات المصحف الصوتية المساعدة، وأول تشغيل للمحرك ينزّل كذلك ملفات WebAssembly. لا تُرفع تسجيلات صوتية إلى خادم.

## ما ينفذه النموذج

- مصحف المدينة لحفص بصفحات متصلة، من دون إعادة كتابة أو تغيير النص القرآني؛ تنقل بالصفحة والسورة، وعلامات وملاحظات محلية، ووضع قراءة غامر.
- زر التسميع من الصفحة الحالية يجهز نطاق السورة الأولى في الصفحة. إذا احتوت الصفحة أكثر من سورة، لا يدّعي اختيارها كلها.
- متابعة محلية للكلمات، أو تسميع سورة ونطاق آيات محددين، وكلمات مخفية تظهر عند متابعة المحرك لها.
- تلميح كلمة واحدة، ومعاينة الصفحة عند الحاجة. يبقى التلميح مسجلًا للمراجعة حتى لو تابع المحرك الكلمة بعد ذلك، وتُذكر معاينات الصفحة في الجلسة.
- نتائج محلية لآخر 30 جلسة، تعرض التلميحات والمواضع التي لم يتابعها المحرك بوضوح، مع زر للعودة إلى آيتها. جلسة بلا كلمات لا تُحسب نجاحًا أو خطأ في القراءة.
- سجل الجلسات وعدد أيام التسميع الفعلية في آخر سبعة أيام بدل أرقام تقدم ثابتة. هذه ليست نسبة حفظ ولا تقييم تجويد. يمكن حذف سجل الجلسات بعد تأكيد.
- يحتفظ الجهاز بواجهة النسخة المبنية والصفحات المفتوحة وبياناتها للعمل دون اتصال. صفحة جديدة تحتاج اتصالًا، وقد يمسح النظام التخزين المحلي. لا توجد حسابات أو مزامنة.

## حدود يجب معرفتها

المتابعة تقريبية وقد تخطئ في الموضع أو الكلمة، ولا تُقيّم الحركات أو التجويد تقييمًا موثوقًا. لم تُثبت دقتها على صوت المستخدم أو ضوضاء حقيقية أو Safari على iPhone. اللون الأخضر يعني أن المحرك تابع الكلمة، وليس شهادة بصحة التلاوة. المواضع الكهرمانية ترشيحات للمراجعة، وليست أخطاء مؤكدة. لا توجد نسبة دقة مصطنعة.

يُوقف الميكروفون عند مغادرة الصفحة أو انتقالها للخلفية. إذن الميكروفون، رفضه، استعادة التطبيق، سرعة المحرك، حرارة الجهاز والعمل دون اتصال تحتاج اختبارًا على iPhone فعلي قبل أي نشر. يستخدم الإدخال الصوتي حاليًا ScriptProcessor، وهو API قديم يحتاج ترقية لاحقة إلى AudioWorklet.

الخطة اليومية في تبويب اليوم ما زالت مثالًا موضحًا، ولم تُنفذ خطة حفظ كاملة أو مراجعة سحابية أو حسابات أو مزامنة أو اشتراك مدفوع.

## الاختبارات

```sh
npm test
npx playwright install chromium
npm run build
npm run test:ui
REAL_ASR=1 npm run test:ui
```

اختبار المتصفح يستخدم Chrome الموجود في `/usr/bin/google-chrome` افتراضيًا؛ مرّر `CHROME_PATH` لمسار Chromium عند الحاجة. يختبر المسار الفرعي `/rattil-app/`، المظهر على عرض هاتف، التلميحات، أحداث متابعة اصطناعية، حفظ النتائج واستعادتها، التقدم، وصول الفلق والناس إلى صفحة 604، تأكيد الحذف وإلغاءه، والواجهة والصفحة المفتوحة دون اتصال. `REAL_ASR=1` يختبر تهيئة النموذج الحقيقي ومسارات أصوله فقط، لا دقة التعرف على تلاوة بشرية.

## النشر لاحقًا

تعديل إعداد Pages موجود على الفرع لإنتاج ورفع `dist/` بدل المصدر. لا يعمل النشر من هذا الفرع، حتى عند تشغيل workflow يدويًا، لأن مهمة النشر مقيدة بفرع `main`. الدمج والنشر خطوة لاحقة تحتاج الموافقة، ولا ينفذهما هذا النموذج.
